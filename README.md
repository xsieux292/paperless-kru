# KruAssist — ระบบ AI ช่วยงานเอกสารครู

เว็บแอปสำหรับคุณครู — ส่งเอกสารให้ AI ทำแทน และทำเรื่องเบิกงบ/ยืมพัสดุได้ในที่เดียว

แปลงมาจากไฟล์ HTML ต้นฉบับ (`legacy/teacher_document_upload_portal.html`) เป็นโปรเจกต์ React + TypeScript แบบ production
ปรับดีไซน์ทั้งระบบตาม `archive/new UX,UI/plan.md` พร้อมข้อมูลจำลอง (mock) ที่ใช้งานได้จริงทั้งระบบ
และชั้น API ที่เตรียมไว้ให้สลับไปต่อ backend จริงได้โดยไม่ต้องแก้ UI

## 2 หน้าเว็บในโปรเจกต์นี้

| หน้า | URL | ใช้ทำอะไร |
| --- | --- | --- |
| **ระบบจริง** | `/` | เว็บที่คุณครูใช้งานจริง — ส่งเอกสารให้ AI และเบิกงบ/ยืมพัสดุ |
| **Prototype LINE OA** | `/line-demo.html` | จำลอง user journey บน LINE OA ไว้นำเสนอ (ไม่ได้ต่อ LINE จริง) |

### หน้า "ระบบจริง" มี 2 เมนู (กลุ่ม Doc Done)

**1. ส่งเอกสารให้ AI** — เลือกได้ 3 บริการ
- เติมข้อมูลลงแบบฟอร์ม — **เลือกแบบฟอร์มที่เคยส่งไว้แล้วได้เลย ไม่ต้องอัปโหลดไฟล์เดิมซ้ำ**
  (เรียงตัวที่ใช้บ่อยขึ้นก่อน) หรือจะอัปโหลดแบบฟอร์มใหม่ก็ได้
- แปลงรูปถ่ายเป็นเอกสาร
- ทำบัญชีจากใบเสร็จ — **ต้องระบุว่าเป็นของโครงการไหน และเป็นใบเสร็จค่าอะไร**
  เพื่อให้รายงานแยกตามโครงการ ไม่ปนกัน (มีเตือนเมื่องบโครงการใกล้เต็ม)

**2. เบิกงบ / ยืมพัสดุ** (Flow B ในแผน UX) — ฟอร์ม 3 ขั้นตอนพร้อมแถบความคืบหน้า
- ขั้น 1 ข้อมูลคำขอ: เบิกงบซื้อของ หรือ ยืมพัสดุ · เรื่อง · โครงการ (เห็นงบคงเหลือ) · วันที่ต้องใช้
- ขั้น 2 รายการที่ต้องการ: กรอกเองได้ หรือกด **"ให้ AI ช่วยคิดรายการอุปกรณ์"**
  พิมพ์สั้น ๆ ว่าจะจัดกิจกรรมอะไร → AI เสนอรายการ + ราคาประมาณ → เลือกใส่ในใบเบิก
- ขั้น 3 ผู้อนุมัติ + ตรวจทาน: เตือนถ้ายอดเกินงบคงเหลือ แล้วส่งให้ผู้อนุมัติเซ็น
- มีรายการ **"ใบเบิกของฉัน"** กรองตามสถานะ (รออนุมัติ / อนุมัติแล้ว / ถูกตีกลับ พร้อมเหตุผล)

## เทคโนโลยีที่ใช้

- **React 18 + TypeScript** (strict mode)
- **Vite 6** — dev server และ bundler
- **Tailwind CSS 3** — design token ตาม `archive/new UX,UI/plan.md` อยู่ใน `tailwind.config.js`
- **TanStack Query 5** — จัดการ state ของข้อมูลจาก API, cache, retry และ polling
- **lucide-react** — ไอคอน (แทน Font Awesome CDN เดิม เพื่อไม่ต้องพึ่ง CDN ตอน production)

## การสลับจากข้อมูลจำลองไปใช้ API จริง

ทุกฟังก์ชันใน `src/api/*.api.ts` มีรูปแบบเดียวกัน:

```ts
export async function fetchJobs(): Promise<Job[]> {
  if (env.useMock) return mockServer.listJobs();          // โหมดจำลอง
  const raw = await http.get<Job[]>(endpoints.jobs.list()); // API จริง
  return raw.map(normalizeJob);
}
```

**ขั้นตอนการต่อ backend จริง**

1. คัดลอกไฟล์ตั้งค่า

   ```bash
   cp .env.example .env
   ```

2. แก้ `.env`

   ```
   VITE_API_BASE_URL=https://api.your-school.ac.th/v1
   VITE_USE_MOCK=false
   ```

3. ถ้าชื่อฟิลด์จาก backend ไม่ตรงกับ `src/types/index.ts` ให้แก้ที่ฟังก์ชัน `normalizeJob()` / `normalizeProfile()`
   **เท่านั้น** — ไม่ต้องแตะโค้ด UI เลย

### สัญญา API ที่ระบบคาดหวัง

| Method | Path | ใช้ทำอะไร |
| --- | --- | --- |
| `GET` | `/me` | ข้อมูลครูที่ล็อกอินอยู่ → `TeacherProfile` |
| `GET` | `/jobs` | รายการงานทั้งหมด → `Job[]` |
| `GET` | `/jobs/:id` | รายละเอียดงานเดียว → `Job` |
| `POST` | `/jobs` | สร้างงานใหม่ (multipart: `mode`, `notes`, `files[]`) → `{ jobId, status }` |
| `POST` | `/jobs/:id/retry` | สั่งทำงานใหม่เมื่อ job ล้มเหลว → `Job` |
| `POST` | `/jobs/:id/cancel` | ยกเลิกงาน |
| `GET` | `/jobs/:id/files/:fileId` | ดาวน์โหลดไฟล์ผลลัพธ์ (binary) |
| `GET` | `/form-templates` | แบบฟอร์มที่เคยอัปโหลดไว้ → `FormTemplate[]` |
| `GET` | `/projects` | โครงการ/งบประมาณ → `Project[]` |
| `GET` | `/requisitions` | ใบเบิกของฉัน → `Requisition[]` |
| `POST` | `/requisitions` | สร้างใบเบิกใหม่ → `Requisition` |
| `POST` | `/requisitions/suggest-items` | AI คิดรายการจาก `{ description }` → `SuggestedItem[]` |
| `GET` | `/requisitions/approvers` | รายชื่อผู้อนุมัติ → `Approver[]` |

ตอนสร้างงาน (`POST /jobs`) จะแนบฟิลด์เพิ่มมาใน multipart ด้วยเมื่อมีค่า:
`formTemplateId` (ใช้แบบฟอร์มเดิม), `projectId` และ `receiptCategory` (แยกงานบัญชี)

- รองรับ response ทั้งแบบส่งตรง และแบบห่อ envelope `{ "data": ... }`
- แนบ token อัตโนมัติจาก `localStorage.getItem('auth_token')` (แก้จุดเดียวได้ที่ `src/api/http.ts`)
- ระบบจะถามสถานะงานซ้ำทุก 3 วินาที **เฉพาะตอนที่ยังมีงานค้างอยู่** แล้วหยุดเองเมื่อทุกงานเสร็จ

## การปรับดีไซน์ตาม archive/new UX,UI/plan.md

| หลักการในแผน | ทำอะไรในโค้ด |
| --- | --- |
| ① หนึ่งจอ = หนึ่งงาน = หนึ่งปุ่มหลัก | ปุ่มทึบมีได้ปุ่มเดียวต่อจอ — ก่อนเลือกไฟล์ ปุ่มทึบคือ "ถ่ายรูป/เลือกไฟล์" พอมีไฟล์แล้วย้ายไปที่ปุ่มส่ง |
| ② ปุ่มหลักติดล่างจอ สูง 56px | `h-btn` = 56px, `h-btn-sm` = 48px, มุมโค้ง 12px (`rounded-btn`) และแถบปุ่มลอยล่างจอบนมือถือ |
| ③ ปุ่มเป็น "กริยา + สิ่งของ" | ป้ายปุ่มเปลี่ยนตามบริการ เช่น "ส่งใบเสร็จให้ AI ทำบัญชี", "ถ่ายรูปใบเสร็จ" |
| ④ ไอคอนมีข้อความคู่เสมอ | ทุกช่อง Rich Menu และปุ่มไอคอน (ลบไฟล์ / รีเฟรช) มีข้อความกำกับ |
| ⑤ สีมีความหมายเดียว | เขียว = เรียบร้อย/ปุ่มหลัก · ส้ม = ตรงนี้รอคุณอยู่ · แดง = มีปัญหา · เทา = อ่านอย่างเดียว (ชื่อสีใน `tailwind.config.js` ตั้งตามความหมาย ไม่ใช่ตามเฉดสี) |
| ⑥ AI ทำก่อน ครูแค่ตรวจ | หน้าตรวจ OCR ไฮไลต์เฉพาะช่องที่ AI ไม่มั่นใจ + "ให้ AI ช่วยคิดรายการอุปกรณ์" ในใบเบิก |
| ⑦ ไม่มีทางตัน | ทุกจอมีย้อนกลับ/เก็บเป็นร่าง/ถามเจ้าหน้าที่ และบอกเหตุผลทุกครั้งที่ยังกดส่งไม่ได้ |
| ⑧ ใช้ภาษาโรงเรียน | "ใบเบิก" "เรียนฟรี 15 ปี" "งบพัสดุหมวดวิชา" "ว.PA" — ไม่มี Submit / Sync / Dashboard |
| Design system | ฟอนต์ Noto Sans Thai / IBM Plex Sans Thai · เนื้อหา ≥16px · ตัวเลขเงิน 24px · พื้นที่กดได้ ≥48px |
