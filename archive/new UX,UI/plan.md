# KruAssist — UX/UI Design Plan บน LINE OA (ฉบับรวม)

*ระบบ AI ช่วยงานเอกสารครู — 2 กลยุทธ์: Doc Done + Teach & Grow*

---

## 1. เป้าหมายการออกแบบ

> **"ครูเปิดหน้าจอมา ภายใน 3 วินาที ต้องรู้เองว่าต้องกดตรงไหน"**

ครูใช้มือถือระหว่างคาบ มีเวลาว่างครั้งละ 2–5 นาที และหลายคนไม่คุ้นแอปใหม่ ทุกการตัดสินใจด้านดีไซน์จึงต้องตอบโจทย์นี้ก่อนความสวยงาม

**ตัวชี้วัดความสำเร็จ**
| ตัวชี้วัด | เกณฑ์ |
|---|---|
| First-Tap Test | ครู 4/5 คน กดถูกภายใน 5 วินาที |
| 5-Second Test | ครู 4/5 คน บอกได้ว่าหน้านั้นให้ทำอะไร |
| งานหลัก (ถ่ายใบเสร็จ) | จบภายใน 3 tap / 90 วินาที |
| อัตราทิ้งกลางทาง | < 15% ต่อ flow |

## 2. หลักการออกแบบ 8 ข้อ (ใช้กับทุกหน้าจอ)

**① หนึ่งจอ = หนึ่งงาน = หนึ่งปุ่มหลัก**
ปุ่มสีทึบมีได้ปุ่มเดียวต่อจอ ปุ่มอื่นเป็นตัวอักษรธรรมดาหรือขอบบาง

**② ปุ่มหลักติดล่างจอเสมอ กว้างเต็มขอบ สูง 56px**
ตำแหน่งเดิมทุกหน้าจอ = ครูจำได้โดยไม่ต้องคิด และนิ้วโป้งเอื้อมถึง

**③ ปุ่มเขียนเป็น "กริยา + สิ่งของ" ห้ามคำเดียวลอย ๆ**

| ❌ | ✅ |
|---|---|
| ตกลง / ยืนยัน / ถัดไป | ส่งใบเบิกให้ผู้อำนวยการ |
| อัปโหลด | ถ่ายรูปใบเสร็จ |
| ดำเนินการต่อ | ไปกรอกรายการอุปกรณ์ |

**④ ไอคอนต้องมีข้อความคู่เสมอ** ห้ามไอคอนเดี่ยว รวมถึงใน Rich Menu

**⑤ สีมีความหมายเดียวตลอดระบบ**

| สี | ความหมาย (ห้ามใช้ผิดวัตถุประสงค์) |
|---|---|
| 🟠 ส้ม `#F5A623` | **"ตรงนี้รอคุณอยู่"** — ปุ่มหลัก + ช่องที่ต้องแก้ |
| 🟢 เขียว `#2E7D5B` | เรียบร้อยแล้ว |
| 🔴 แดง `#D64545` | มีปัญหา ต้องแก้ |
| ⚪ เทา `#9E9E9E` | อ่านอย่างเดียว / ยังไม่ถึงตา |

ห้ามใช้ส้มเป็นสีตกแต่งเด็ดขาด

**⑥ AI ทำก่อน ครูแค่ตรวจ — ไฮไลต์เฉพาะจุดที่ต้องแตะ**
ช่องที่ AI มั่นใจ = พื้นเทา มีเครื่องหมายถูก / ช่องที่ไม่มั่นใจ = พื้นส้ม ขอบส้ม มีข้อความชี้นำ พร้อมบอกจำนวน "แก้แค่ 1 ช่องพอ"

**⑦ ไม่มีทางตัน** ทุกจอมี ① ย้อนกลับมุมซ้ายบน ② "เก็บเป็นร่างไว้ก่อน" ③ "ถามเจ้าหน้าที่"

**⑧ ใช้ภาษาโรงเรียน** — "ใบเบิก" "ใบยืมของ" "หัวหน้าฝ่าย" "ว.PA" ห้าม Submit / Sync / Dashboard

## 3. สถาปัตยกรรมระบบ — "แชทคือทางเข้า, LIFF คือทางทำงาน"

| งาน | UI | เหตุผล |
|---|---|---|
| แจ้งเตือน สรุป ยืนยัน | Chat (Flex + Quick Reply) | เร็ว ไม่ต้องโหลดหน้าใหม่ |
| กรอกฟอร์ม ถ่ายรูป ดู portfolio | LIFF | ต้องการ input เยอะ + กล้อง |
| นำทางทั้งระบบ | Rich Menu | ถึงใน 1 tap อยู่ติดจอตลอด |

**กฎเสริม:** หน้า LIFF ยาวไม่เกิน 1.5 scroll ถ้าเกินให้ตัดเป็น step และแสดง "ขั้นที่ 2 จาก 3" + progress bar เสมอ

### Rich Menu (2500 × 1686 px, 6 ช่อง, สลับ 2 แท็บด้วย richmenuswitch)

**แท็บ A — Doc Done**
```
┌──────────────┬──────────────┬──────────────┐
│ 📸 ถ่ายใบเสร็จ │ 📝 เบิกงบ/พัสดุ │ ✍️ รอฉันเซ็น ●3│
│  (ทึบเข้ม)    │              │              │
├──────────────┼──────────────┼──────────────┤
│ 📂 เอกสารของฉัน│ 💰 สรุปงบ     │  ▶ Teach&Grow │
└──────────────┴──────────────┴──────────────┘
```

**แท็บ B — Teach & Grow**
```
┌──────────────┬──────────────┬──────────────┐
│ 📅 แผนการสอน  │ 🏆 งานแข่ง/อบรม│ 📊 ผลนักเรียน │
│  (ทึบเข้ม)    │              │              │
├──────────────┼──────────────┼──────────────┤
│ 📁 Portfolio  │ 🤖 ถาม AI     │  ◀ Doc Done  │
└──────────────┴──────────────┴──────────────┘
```

**กฎ Rich Menu**
- ช่องซ้ายบน = งานที่ทำบ่อยสุด → พื้นทึบเข้ม ตัวหนังสือขาว (อีก 5 ช่องพื้นขาว) ตาจะวิ่งไปหาก่อนเสมอ
- งานค้าง → จุดส้ม + ตัวเลข มุมขวาบนของช่อง (สร้าง 3 เวอร์ชัน: 0 / 1–9 / 9+ แล้ว `linkRichMenuToUser`)
- แถบสลับแท็บ อยู่ล่างสุดเต็มความกว้าง มีลูกศร ◀ ▶
- เส้นแบ่งช่องหนา 3px เพื่อสื่อว่าแตะได้เป็นช่อง ๆ

## 4. Idea 1 — Doc Done *"Snap. Sign. Done."*

### Flow A: ถ่ายใบเสร็จ → ลงบัญชี ⭐ **flow สำคัญสุด ทำก่อน**

| ขั้น | หน้าจอ | จุดออกแบบ |
|---|---|---|
| 1 | Rich Menu | ช่องทึบเข้มซ้ายบน |
| 2 | LIFF: กล้อง | เปิดกล้องทันที ไม่มีหน้าคั่น + กรอบไกด์วางใบเสร็จ |
| 3 | LIFF: ตรวจข้อมูล | ช่องถูก = เทา+✓ / ช่องต้องแก้ = ส้ม+ขอบ 2px + แถบบอก "แก้แค่ 1 ช่องพอ" |
| 4 | LIFF: เลือกหมวดงบ | Chip ใหญ่ 3–4 อัน (เรียนฟรี 15 ปี / กิจกรรม / พัสดุ) |
| 5 | Chat: Flex สรุป | การ์ดรูปใบเสร็จ + ปุ่ม "ยืนยันด้วย OTP" |
| 6 | Chat | กรอก OTP → การ์ดเปลี่ยนเป็น ✅ พร้อมบอกขั้นถัดไป |

### Flow B: เบิกงบ / ยืมพัสดุ + ขอลายเซ็นคนอื่น
- ฟอร์ม 3 step มี progress bar
- ช่อง "รายการอุปกรณ์" มีปุ่ม **🤖 ให้ AI ช่วยคิด** → พิมพ์ว่าจะจัดกิจกรรมอะไร → AI คืนรายการ + ราคาประมาณ กดเลือกทีละรายการเข้าฟอร์ม
- ส่งแล้ว → ผู้อนุมัติได้ Flex ในแชทตัวเอง: `[ดูเอกสาร] [เซ็นอนุมัติ] [ตีกลับ]`

### Flow C: e-Signature + OTP ⭐ **จุดที่ครูกังวลที่สุด — ต้องออกแบบให้อุ่นใจ ไม่ใช่รีบกด**

โครงหน้าจอจากบนลงล่าง
1. ไอคอนกุญแจ + หัวเรื่อง "ยืนยันการเซ็นเอกสาร"
2. กล่องสรุปสีเทา — เซ็นให้ใคร / เอกสารอะไร / **ยอดเงินตัวใหญ่ 24px**
3. บรรทัดเตือนใจ **สีเทาเข้ม ไม่ใช่สีแดง**: *"ลายเซ็นนี้มีผลผูกพันตามระเบียบราชการ โปรดตรวจสอบยอดก่อนยืนยัน"*
4. ช่อง OTP **6 ช่องแยกกัน** ตัวเลข 24px
5. Timer นับถอยหลัง + "ขอรหัสใหม่"
6. ปุ่มเดียว "ยืนยันการเซ็น"
7. สำเร็จ → เด้ง **การ์ดหลักฐาน** เข้าแชท (เซ็นเมื่อไร เลขที่เอกสารอะไร) ครูเก็บไว้ในแชทเองได้

### Flow D: เอกสารของฉัน
List view + filter chip `ทั้งหมด | ร่าง | รออนุมัติ | อนุมัติแล้ว | ตีกลับ` ใช้จุดสีสถานะ + ไอคอน + ข้อความ (ไม่พึ่งสีอย่างเดียว)

## 5. Idea 2 — Teach & Grow *"Plan Smarter. Grow Faster."*

### Flow E: Smart Syllabus
- ปฏิทิน **week view** (ไม่ใช่ month) แต่ละคาบเป็นการ์ด
- เมื่อมีอบรม/กิจกรรมแทรก → Flex เข้าแชท:
  > "12 ส.ค. มีอบรม ทับคาบ ม.2/3 — AI เลื่อนแผนให้แล้ว
  > **[ดูแผนใหม่] [เลื่อนเอง] [ไม่ต้องเลื่อน]**"

  นี่คือ pattern หลักของทั้งระบบ: **AI ทำให้ก่อน แล้วให้ครูกดยืนยัน/แก้**

### Flow F: Student Insight (PDPA-safe)
- Dashboard ระดับ**ห้อง** ไม่ใช่รายคน (bar chart คะแนน + radar SDQ)
- รายชื่อแสดงเป็นรหัส/ชื่อย่อ by default มีปุ่ม unlock ดูชื่อเต็ม
- AI สรุปเป็นการ์ด "3 ข้อสังเกตของห้องนี้" + คำแนะนำการสอน
- **Badge ถาวรบนหน้า: "ข้อมูลถูกไม่ระบุตัวตนก่อนส่งให้ AI"**

### Flow G: Auto Portfolio ว.PA
- **Timeline UI** เรียงตามเวลา: งานสอน / พาแข่ง / อบรม / ผลงานนักเรียน
- ปุ่มลอย ➕ → ถ่ายรูป + พิมพ์สั้น ๆ → AI เขียนคำบรรยายภาษาราชการให้
- แถบบน: **ความครบถ้วน 68%** + ระบุว่าขาดด้านไหน
- ปุ่มเดียว "Export PDF ตามแบบ ว.PA" — เทมเพลตเดียวกันทุกคน **ไม่มีให้ตกแต่ง** (หลักความเท่าเทียม ครูไม่ต้องแข่งความสวยของพอร์ต)

### Flow H: AI Advisor
Push Flex Carousel สัปดาห์ละครั้ง การ์ดละ 1 รายการแข่ง + `[สนใจ] [ไม่ตรงสายฉัน]` — ปุ่มหลังใช้ปรับความแม่นรอบถัดไป

## 6. Design System

| หัวข้อ | กำหนด |
|---|---|
| สีหลัก | Doc Done เขียว `#2E7D5B` · Teach & Grow น้ำเงิน `#2C6BB0` · Accent ส้ม `#F5A623` |
| ฟอนต์ | Noto Sans Thai / IBM Plex Sans Thai |
| ขนาดตัวอักษร | เนื้อหา ≥16px · หัวเรื่อง 20px · ตัวเลขเงิน 24px |
| ปุ่ม | สูง 56px (ปุ่มหลัก) / 48px (รอง) มุมโค้ง 12px |
| พื้นที่กดได้ | ≥48×48px ทุกจุด รวมปุ่มย้อนกลับ |
| ระยะห่างปุ่ม | ≥12px กันกดพลาด |
| Contrast | ≥4.5:1 ห้ามเทาอ่อนบนขาว |
| ไม่พึ่งสีอย่างเดียว | สถานะ = สี + ไอคอน + ข้อความ |
| Voice input | ทุกช่องข้อความรองรับ (ครูหลายคนพิมพ์ช้า) |
| Flex bubble | `mega` สำหรับสรุปเอกสาร · `kilo` สำหรับแจ้งเตือน |
| Empty state | ต้องมีทุกหน้า เช่น "ยังไม่มีเอกสารรออนุมัติ 🎉" |

## 7. Microcopy & Feedback

**ห้ามใช้คำว่า Error / Failed / Invalid** เขียนเป็นภาษาคนเสมอ

| จังหวะ | สิ่งที่ครูต้องเห็น |
|---|---|
| กดปุ่ม | ปุ่มยุบเล็กน้อยทันที (< 100ms) |
| กำลังโหลด | ปุ่มเปลี่ยนเป็น "กำลังส่ง…" ไม่ใช่หมุนเปล่า |
| สำเร็จ | ✓ เขียว + **บอกว่าเกิดอะไรต่อ** "ส่งให้ ผอ. แล้ว รอผลภายใน 2 วัน" |
| ผิดพลาด | บอกวิธีแก้เสมอ "รูปเบลอ ลองถ่ายใหม่ให้มีแสงมากขึ้น" + ปุ่มถ่ายใหม่ |

## 8. Onboarding — 3 หน้าจอ จบใน 30 วินาที

ไม่ใช่ tutorial ยาว แต่เป็นการ**กดจริง 1 ครั้ง**

1. "สวัสดีครู[ชื่อ] ลองถ่ายใบเสร็จอะไรก็ได้ 1 ใบ" → ปุ่มถ่ายเลย
2. ระบบอ่านให้ดู → ครูเห็นด้วยตาตัวเองว่ามันทำงาน (สร้างความเชื่อใจดีกว่าคำอธิบาย 10 หน้า)
3. "เก็บลายเซ็นของครูไว้ก่อน" → เซ็นบนจอ 1 ครั้ง + อธิบายสั้นว่าทุกครั้งที่ใช้ต้องยืนยัน OTP คนอื่นเอาไปใช้ไม่ได้

จบแล้วขึ้น coach mark ชี้ Rich Menu 1 ครั้ง แล้วไม่ขึ้นอีก

## 9. Notification Strategy

⚠️ LINE Notify ปิดบริการแล้ว → ใช้ **Messaging API push message** (ตรวจโควตา push ของแพ็กเกจ OA ก่อนวางแผนความถี่)

| ประเภท | เวลา | รูปแบบ |
|---|---|---|
| งานรอเซ็น | ทันที | Flex + ปุ่มเซ็นในการ์ด |
| สรุปงานค้าง | จันทร์ 07:30 | Flex สรุป |
| เตือน deadline ว.PA | ล่วงหน้า 14/7/1 วัน | Flex + ปุ่มไป Portfolio |
| งานแข่ง/อบรม | ศุกร์ 16:00 | Carousel |

**กฎ:** ไม่เกิน 1 push/วัน (ยกเว้นงานรอเซ็น) และมีหน้าตั้งค่าให้ปิดแยกประเภทได้

## 10. Roadmap

**Phase 1 — Demo/Pitch (12 หน้าจอ)**
Rich Menu ×2 · Flow A ครบ 6 จอ · Flow C (OTP + การ์ดหลักฐาน) · Flow G (Portfolio timeline + Export)
→ ครอบคลุมทั้ง 2 idea และโชว์จุดต่างที่คู่แข่งไม่มี: **OCR + OTP + Auto Portfolio**

**Phase 2** — Flow B, E, H · Onboarding 3 จอ · หน้าตั้งค่าแจ้งเตือน

**Phase 3** — Flow F (ต้องเคลียร์ PDPA กับโรงเรียนก่อน)

### Screen list รวม (~24 จอ)
```
Rich Menu ×2
Doc Done   : กล้อง → ตรวจ OCR → เลือกหมวด → Flex สรุป → OTP → สำเร็จ
             ฟอร์มเบิก 3 step → AI ช่วยคิดอุปกรณ์ → การ์ดขออนุมัติ
             เอกสารของฉัน → รายละเอียดเอกสาร
Teach&Grow : ปฏิทินสัปดาห์ → รายละเอียดคาบ → การ์ดแจ้งชนตาราง
             Dashboard ห้อง → การ์ด AI insight
             Portfolio timeline → เพิ่มผลงาน → Export preview
             Carousel งานแข่ง
Common     : Onboarding ×3, ตั้งค่าแจ้งเตือน, ลงทะเบียนลายเซ็น
```

## 11. ความเสี่ยงที่ต้องเช็กก่อนลงมือ

| ความเสี่ยง | สิ่งที่ต้องทำ |
|---|---|
| **PDPA** ข้อมูลนักเรียน | ทำ anonymize ก่อนส่ง AI + ขอความยินยอมจากโรงเรียน (Flow F ไว้ Phase 3) |
| **ผลทางกฎหมายของ e-Signature** | ตรวจว่ารูปแบบลายเซ็น + OTP ตรงตาม พ.ร.บ.ธุรกรรมทางอิเล็กทรอนิกส์ และระเบียบพัสดุภาครัฐหรือไม่ |
| **ระบบเอกสารกลางของโรงเรียน** | เอกสารเบิกจ่ายราชการมักต้องเป็นแบบฟอร์มเฉพาะ — ต้องเช็กว่ายื่นแบบดิจิทัลได้จริงไหม ไม่งั้นต้อง export เป็น PDF ตามแบบ |
| **โควตา push ของ LINE OA** | คำนวณจำนวนครู × ข้อความ/เดือน ก่อนเลือกแพ็กเกจ |
