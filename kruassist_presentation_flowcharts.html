🗣️ คำบรรยายสำหรับผู้นำเสนอ (Speaker Notes)

"ภาพนี้คือสถาปัตยกรรมของ KruAssist ปัจจุบันครับ ฝั่งซ้ายคือ UI ที่เสร็จสมบูรณ์ 100% ทั้งบนเว็บและ LINE ข้อดีของโครงสร้างนี้คือ 'โค้ดฝั่ง UI จะไม่รู้จัก URL ของ Backend เลย' ทุกอย่างจะวิ่งผ่าน API Layer ตรงกลางจุดเดียว ปัจจุบันระบบวิ่งเข้า Mock Server แต่เมื่อ Backend จริงพร้อม เราแค่เปลี่ยนค่าสวิตช์ในไฟล์ .env ระบบก็จะชี้ไปหา Backend จริงทันทีโดยไม่ต้องแก้โค้ดหน้าจอเลยครับ"

2. การทำงานแบบ Asynchronous ของระบบ AI

จุดประสงค์: อธิบายว่า Frontend สื่อสารกับ AI อย่างไรโดยที่หน้าเว็บไม่ค้าง และครูไม่ต้องกดรีเฟรชหน้าจอเอง

🗣️ คำบรรยายสำหรับผู้นำเสนอ (Speaker Notes)

"เนื่องจากการประมวลผล AI (เช่น อ่าน OCR) ใช้เวลา ระบบจึงออกแบบมาเป็น Asynchronous เมื่อครูอัปโหลดเอกสาร Backend จะรับคิวและตอบกลับทันที จากนั้น Frontend จะทำการ Polling หรือถามสถานะงานทุกๆ 3 วินาทีอัตโนมัติ เพื่ออัปเดต Progress Bar พอ AI ทำงานเสร็จ ระบบจะส่งผลลัพธ์กลับมา พร้อมกับค่า Confidence Score เพื่อให้หน้าจอไฮไลต์สีส้มในจุดที่ AI ไม่มั่นใจ ช่วยให้ครูตรวจสอบงานได้เร็วขึ้นครับ"

🗣️ คำบรรยายสำหรับผู้นำเสนอ (Speaker Notes)

"สำหรับทีมงานที่จะมารับช่วงต่อ การเอา Backend จริงมาต่อกับหน้าเว็บมีเพียง 4 ขั้นตอนสั้นๆ (กล่องสีเหลือง) โดยโฟกัสแก้ไฟล์แค่ 3 จุดเท่านั้น ไม่ต้องยุ่งกับโค้ด UI เลย

ส่วนสิ่งที่ต้องพัฒนาต่อ (กล่องด้านขวา) งานที่ท้าทายที่สุดและต้องให้ความสำคัญก่อนคือ ความแม่นยำของ OCR ลายมือภาษาไทย และ ผลทางกฎหมายของการทำ e-Signature สำหรับเอกสารราชการ ซึ่งเป็นความเสี่ยงทางเทคนิคที่เราต้องทดสอบและหาข้อสรุปก่อนเปิดใช้งานจริงครับ"
